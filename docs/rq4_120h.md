# RQ4 under a 120-hour wall-clock limit

Run `configs/rq4_120h.yaml` into a new `results/rq4_120h` directory. The original `configs/rq4.yaml` and its partial `results/rq4` output remain separate. Rerunning the reduced command after an interruption resumes its own checkpoints.

```powershell
python -m src.experiments --config configs/rq4_120h.yaml --output results/rq4_120h
```

| Component | Original RQ4 | Reduced RQ4 |
| --- | ---: | ---: |
| Datasets | California Housing, Diabetes Progression | Same |
| Shared outer splits | 5 | 5 |
| Inner folds | 3 | 3 |
| Search seeds | 5 | 2 (`11`, `23`) |
| Learners | OLS, Ridge, 100-tree Random Forest | Same |
| Construction families | Quadratic, RBF | Same |
| Adaptive `k` grid | `0, 1, 2, 4, 8` | Same |
| GA candidates per family, learner, seed, split | 1,000 (250 per positive `k`) | 500 (125 per positive `k`) |
| Forest workers during tuning and candidate scoring | 1 | 8 |
| Total candidate evaluations | 300,000 | 60,000 |
| Three-fold candidate model fits | 900,000 | 180,000 |
| Result rows, including no-FE baselines | 330 | 150 |

The reduction in candidate work is `2/5` search seeds times `500/1000` evaluations, or **80% fewer candidates**. Forest parallelism changes wall time, not the number of trees or candidate fits. Final saved forest models use one worker so their prediction hashes replay exactly. The runner stops at 118 hours of recorded active wall time, leaving a two-hour margin below the 120-hour limit. A stop at the cap would leave partial results and would not support a complete RQ4 conclusion.

The two families come from the earlier exploratory findings: RQ1 favored construction over selection or combined strategies on average; RQ2 found a much larger California Housing gain for RBF and a stronger Diabetes gain for quadratic. RQ3 did not establish a universal optimizer replacement, so GA remains the shared search method. The full `k` grid and five shared outer splits remain for paired comparisons with RQ1–RQ3. The two search seeds make stochastic variability less precise. The smaller search budget can understate FE benefit: in RQ2, California RBF's median best inner MAE still improved about 1.7% between evaluations 80 and 250 within a `k` search.

The runtime estimate uses California Housing full-size, three-fold forest candidate timings on the current 12-core machine with eight workers and the first split's tuned `min_samples_leaf=1`: eight sampled candidates across both families and `k=1,2,4,8` took 7–43 seconds each, averaging about 15.5 seconds. The first 25 live forest candidates took 190 seconds, or 7.6 seconds each, consistent with the `k=1` sample. The reduced RQ4 has 10,000 California forest candidates, giving about 43 hours at the eight-`k`-sample average. Diabetes forest searches, linear learners, tuning and output writes add several hours. **Plan for roughly 50–100 hours of active wall time** because candidate cost and the selected forest parameter can change across splits. This is a planning estimate, not a guaranteed finish time; `progress.json` and the 118-hour cap show actual consumption.

This RQ4 is an exploratory comparison under a constrained search budget. Its FE results should be compared with each learner's own no-FE baseline within the reduced run. Differences from earlier 1,000-candidate RQ1–RQ3 runs include both learner and optimization budget, so they do not isolate a learner effect across those separate studies. The new RQ4 tests learner effects internally because its arms share splits, seeds, folds and candidate budget.
